# リソース予約・ネットワーク検証の回帰テスト

> **最終確認日:** 2026-09-09
> **対象環境:** CPU および LAN 用ランタイム
> **免責事項:** これは「GPU パススルー」や「未審査の公開 PR を完全に安全に実行できる」という認定・保証を意味するものではありません。

本ドキュメントでは、過去に修正された主要な不具合と、それを防ぐための回帰テスト（Regression Test）について説明します。

---

## 修正された問題

### 1. 予約枠リソースの不正な一般貸出の修正
- **問題**: 停止した VM の CPU・RAM だけが返却され、ディスクの削除が完了していない段階で、古い計算ロジックが「予約枠の CPU・RAM が空いた」と誤判定し、一般 Pool に貸し出してしまう不具合がありました。
- **修正後**: 予約全量から、現在その予約に紐づく VM が保持している全リソース（ディスクや GPU 含む）を引いた残りのみを保護するように修正しました。CPU だけが空いていても、ディスクが完全に削除されるまでは、そのスロットを新しい専用 VM や一般 VM に再利用しません。

### 2. 予約の移動・付け替え時の不整合防止
- **問題**: 以前は「予約名」のみで使用台数をカウントしていたため、予約を別の Node や Pool に変更した場合、古い VM が新しい予約を消費していると誤判定される可能性がありました。
- **修正後**: 名前・Node・Pool の所有関係を厳密に検査するようにしました。保持中のリソースが残っている場合は、予約の移動や付け替えを拒否します。また、CPU・RAM のみが返却済みの状態（ディスクは残存）での「提供上限の縮小」も拒否する安全機構を実装しました。

### 3. ネットワーク設定変更の検知漏れ修正
- **問題**: libvirt が生成する MAC アドレスや UUID、所有情報が一致していれば、NAT がルーティングに変更されたり、IPv6 や VM 間通信が許可されてしまっても、それを検知できずに見逃してしまう問題がありました。
- **修正後**: NAT 方式、IPv6 の有無、VM 間のネットワーク隔離状態、ブリッジ、ゲートウェイ、DHCP の範囲、追加 IP・ルート情報も厳密に確認するようになりました。差異（Drift）が検出された場合は新規 VM の作成をブロックし、既存のネットワークを無断で上書きしません。

### 4. ホスト宛ルートの衝突判定
- **問題**: `172.30.240.91` のような CIDR 表記ではないホスト宛のルート設定が、VM 用サブネットとの衝突検査をすり抜けるケースがありました。
- **修正後**: IPv4 においては、単一 IP を `/32` として扱い、VM 用サブネットとの衝突を正確に検査するように修正しました。

## 再現・確認方法

開発やレビューの際は、以下のコマンドで回帰テストを実行してください：

```bash
go test -race -count=1 ./...
go test ./internal/core -run '^$' -fuzz '^FuzzReservationProtection$' -fuzztime=10s
```

### 主な回帰テスト一覧

- `TestReservationSurvivesPartialCleanup`
- `TestReservationCannotMoveOrRetargetWhileHeld`
- `TestPartiallyReleasedReservationPreventsBudgetShrink`
- `TestReservationCorruptionBlocksNewAllocation`
- `TestNetworkSecurityDriftPreservesIdentityButMustFail`
- `TestHostRouteConflictsWithVMSubnet`

### テスト結果について

修正前に存在した12件の問題ケースがすべて失敗すること、および修正後にすべてパスすることを確認しています。

- Go 1.27.1 でのローカルテストと、GitHub Actions 環境での `race/vet` 検証は区別して記録されています。
- これらのネットワーク回帰テストは、明示的な libvirt / nftables のテストダブル（代役）を使用しています。
- **実際の VM の起動** や **実際のパケット遮断の証明** については、別の専用 CI ジョブで検証しています。
